# 命名規則

> [ドキュメント一覧](../README.md) / 区分: 開発規約

## 基本方針

- **役割と意味の明確化**: 名前だけで役割や意味が直感的に理解できる、具体的で検索しやすい命名を行うこと。
- **用語の統一**: 同一の概念に対しては常に同じ単語を使用し、類義語の混在を避けること。
- **不要な省略・和洋折衷の排除**: 意味が伝わりにくい省略形、ローマ字表記、日本語と英語の不自然な混在を避けること。
- **スコープに応じた命名**: スコープが広い名前ほど具体的にし、ローカル変数などスコープが限定される場合は簡潔な命名とすること。
- **真偽値の命名**: 真偽値（bool）には `is`、`has`、`can`、`should` など、状態や条件が明確に伝わる接頭辞を付与すること。
- **関数・メソッドの命名**: 動詞から始め、どのような処理を行うかが明確に伝わる名称とすること。
- **単位の明記**: 単位を持つ値には、必要に応じて `timeoutMs` や `sizeBytes` のように変数名に単位を含めること。

## クラス名の接尾辞（Suffix）

- **DTOクラス**: DTO（Data Transfer Object）クラスの名称末尾には、必ず `Dto` を付与すること。
  - 例: `GameplayViewStateDto`

## 大文字・小文字の使い分け（ケース表記）

- **ローカル変数・引数・プロパティ・関数・メソッド**: `lowerCamelCase` を使用すること。
  - 例: `userName`、`calculateTotal`
- **プライベートフィールド**: クラスの `private` フィールドの先頭にはアンダースコア `_` を付与すること。
  - 例: `_hasRequest`、`_gameplayScore`
- **クラス・構造体・列挙型・インターフェース・型**: `PascalCase` を使用すること。
  - 例: `UserRepository`、`ConnectionState`
- **グローバル定数**: `UPPER_SNAKE_CASE` を使用すること。
  - 例: `MAX_RETRY_COUNT`、`DEFAULT_TIMEOUT_MS`
- **通常の定数**: `PascalCase` を使用すること。
  - 例: `MaxRetryCount`、`DefaultTimeoutMs`

## 略称の扱い

- **2文字の略称**: すべて大文字のまま記述すること。
  - 例: `IO`、`UI`
  - *例外*: `id` については .NET 公式ガイドラインに従い、一般語彙として `Id` を使用すること（例: `UserId`）。
  - 複合名の例: `UserId`、`SectionUI`、`IOManager`
- **3文字以上の略称**: 先頭文字のみを大文字とし、2文字目以降は小文字で記述すること。
  - 例: `USB` → `Usb`、`API` → `Api`、`URL` → `Url`
  - 複合名の例: `UsbDevice`、`usbDevice`、`ApiClient`

## 避けるべき命名

- **曖昧な名前**: 文脈がないと意味が特定できない名前（`data`、`info`、`value`、`temp` など）。
- **1文字変数**: 短いループインデックスの `i` や、2次元座標の `x`・`y` など、明確な慣例がある場合を除き、1文字の名前は避けること。
- **ハンガリアン記法**: 型名を不必要に付与する命名（`pData`, `iCount` など）。
- **二重否定**: 意味が複雑化する二重否定の真偽値名。
